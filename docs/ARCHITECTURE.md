# Architecture

Generated by `/arch`; describes only what exists in code.

## Overview
Expenses come in from a batch file or the portal. Each one passes through an input guard, then
deterministic normalisation, LLM fact extraction, and a pure policy engine. Flags get an
LLM-drafted question. Every decision is stored as a revision and POSTed downstream.

## Components
| Module | Responsibility |
|---|---|
| app/guard.py | schema/length, sanitise, manipulation screen (Decisions API -> Claude -> regex) |
| app/normalize.py | amount/currency/date parsing |
| app/llm.py | Decisions API screen, Claude screen, extraction, question drafting |
| app/policy.py | pure rules -> decision + reasons |
| app/pipeline.py | evaluate (pure) + process (store, POST, notify) + human override |
| app/store.py | SQLite: expenses, decisions, followups |
| app/poster.py | POST /decisions |
| app/server.py | FastAPI REST + SSE; serves static/employee.html and static/finance.html |
| batch.py / eval.py | batch run / labelled-data scoring |

## Decision flow
guard -> (manipulation? reject) -> normalize -> extract -> (injection? reject) -> policy ->
(LLM/guard failed? flag) -> question if flag -> store revision -> POST -> SSE
